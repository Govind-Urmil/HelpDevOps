# EP-022 existing-feature depth audit

All 37 published journeys were structurally revalidated. Launch-priority review covered CrashLoopBackOff, ImagePullBackOff, Pending Pods, container exits, port allocation, state lock, provider authorization, non-fast-forward, detached HEAD, agent offline, Pipeline permissions, disk full, permission denied, Cron, DNS, TLS, HTTP 502, HTTP 503 responsibility routing, and YAML parsing.

The mature journey engine already enforces read-only-first evidence, observable choices, an unclear/escalation branch, rollback for higher-risk actions, recovery verification, official references, review dates, and stated limitations. Those flows were preserved.

## Material improvements

- Every investigation now exposes compact review provenance, applicability, an honest testing boundary, limitations, official references, and the public review policy.
- Fifteen issue guides add exact-error recognition, first safe checks, evidence requirements, dangerous shortcuts, escalation, and entry into the closest complete journey.
- Search indexes these guides and exact error phrases. Zero-result search suggests broader symptoms, local analysis, tools, investigations, and responsibility areas without fabricating a match.

## Cross-tool, evidence, results, decisions and handoff

Relationships connect image pulls to registry/DNS/TLS, port allocation to host listeners, provider authorization to identity ownership, detached HEAD to reflog preservation, and Pipeline permissions to agent identity and credential scope. They explain why a destination may apply without claiming certainty.

Static inspection confirmed the existing Result Contract distinguishes observations, known/unknown findings, limitations, next checks, risk, escalation, and verification. Branches are evidence-labelled and expose an unclear path. Completion summaries and Incident Brief transfers preserve observations, actions, uncertainty, verification, rollback state, and escalation questions without claiming new verification.

All nine deterministic tools retain validation, examples, local processing, actionable errors, limitations, and resource links. Workspace retains explicit-save persistence, schema validation, merge/replace import, corruption rejection, duplicate handling, clear-all controls, storage-unavailable fallback, local export, and sensitive-content blocking.

## Deferred limitations

No new tool or major product surface was justified. Dedicated journeys for port allocation, detached HEAD, Pipeline filesystem permission, and HTTP 503 were not fabricated; entry pages route to the closest supported investigation and state the limitation. Remote checking, collaboration, analytics activation, and AI diagnosis remain out of scope.
