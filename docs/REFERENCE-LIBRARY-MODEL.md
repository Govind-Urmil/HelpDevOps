# Reference Library Model

References explain operational concepts and evidence boundaries. Each reviewed resource owns stable identifiers, summary, aliases, concepts, limitations, relationships, official sources, review dates and a canonical route. References are not diagnostics and must never claim a root cause.

Routine updates belong in `src/resources/references/<id>/`. Add a resource only when it has unique user value and at least one real relationship. Run `npm run validate:references`, tests and build after every change.
