# EP-020 Implementation Report

## Product and UX

The homepage now presents six concrete operational symptoms immediately after Universal Input. The troubleshooting directory repeats these bounded starts, computes its journey count from the registry, and shows decision depth, estimated time, and risk on journey cards. Existing role starts, domain hubs, tools, and workspace flows remain intact.

## Investigation intelligence

Seven new investigations add deterministic three-way evidence branches for Kubernetes rollout stalls, Docker daemon access, Terraform authorization, Linux load, Git authentication, Jenkins Pipeline failures, and AWS throttling or quotas. Cause maps are ordered investigation priorities, explicitly not probability claims. Terminal states summarize the observed path, conclusion boundary, next verification, and handoff record.

## Architecture and privacy

The implementation reuses the existing diagnostic registry, renderer, static routes, browser-local state, and release pipeline. It introduces no dependency, backend, analytics, runtime fetch, or secret handling.

## Accessibility and responsive summary

New cards use semantic links and headings; disclosure uses native details/summary; terminal summaries use description lists; existing focus management and live status remain. Three-column symptom grids collapse to two and one columns, and completion summaries collapse to a single column on narrow screens.
