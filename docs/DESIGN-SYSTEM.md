# HelpDevOps Design System

**Version:** 1.0  
**Status:** Approved Design Direction

## Design Philosophy

HelpDevOps should feel like a serious DevOps engineering workspace, not a tutorial website.

Goals:

- Trustworthy
- Technical
- Helpful
- Fast
- Minimal
- Professional

## Theme

Dark engineering workspace.

Style inspiration:

- GitHub
- Cloudflare
- Linear
- Kubernetes ecosystem

Avoid:

- Flashy landing pages
- Excessive animations
- Generic SaaS appearance

## Color System

Background:
`#0B1220`

Primary Accent:
`#2563EB`

Success:
`#22C55E`

Warnings and errors use standard semantic colors.

## Typography

Main:

- Inter
- Geist
- IBM Plex Sans

Code:

- JetBrains Mono
- Fira Code

## Component Rules

Components must be:

- Reusable
- Accessible
- Responsive
- Consistent

Base components:

- Buttons
- Cards
- Alerts
- Code blocks
- Navigation
- Search
- Tool panels

## Tool Page Template

Every tool:

1. Title
2. Purpose
3. Input
4. Action
5. Result
6. Explanation
7. Limitations
8. Related resources

## EP Strategy

Avoid excessive EP fragmentation.

Target fewer, meaningful releases.

Preferred:

- Foundation EP
- Core Platform EP
- Initial Tool Suite EP
- Growth/SEO EP

Quality gates remain mandatory.

## Final Design Statement

HelpDevOps should look and feel like a reliable DevOps engineer workspace where users solve real problems quickly.
