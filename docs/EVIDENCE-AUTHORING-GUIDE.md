# Evidence Authoring Guide

1. Prefer stable structured output from official commands.
2. Keep collection commands read-only and narrowly scoped.
3. Define required and conflicting structural signals.
4. Author only synthetic or redacted fixtures.
5. Map extracted fields to observations, not conclusions.
6. Add reviewed interpretations separately.
7. List mandatory unknowns and unsupported contexts.
8. Link only to a reviewed diagnostic journey.
9. Add privacy caveats for operational identifiers and credentials.
10. Run `npm run validate:evidence`, unit tests, build validation, and package hygiene checks.
