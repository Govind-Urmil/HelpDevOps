# Diagnostic Authoring Guide

Start with an observable symptom, not a guessed cause. Gather primary official references, define the first read-only checks, enumerate discriminating evidence, and ensure every branch has an unclear or escalation option. Use synthetic, redacted examples only.

For each modifying action document prerequisites, intended scope, risk, rollback, verification, and escalation conditions. Never recommend deletion, restart, capacity, permission, taint, request, or placement changes merely because they are common fixes.

Run `npm run validate:diagnostics`, `npm test`, and `npm run build`. A journey may be published only with `reviewed` status, current review metadata, authoritative references, passing fixtures, and independent technical review evidence.
